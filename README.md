# BLADE Evaluation Artifact

This repository is the reproducibility artifact for the empirical evaluation of **BLADE**. It is not the BLADE framework.

The canonical implementation is:

- Repository: https://github.com/alanveloso/blade
- Evaluated commit: `c145305a3ca76f52a64b62a0cb731283dbba9638`

Raw records retain the frozen campaign identifier `blade-core-eval-v2`; this identifies the experimental campaign, not a BLADE software version.

## What was evaluated

The evaluation compares:

1. **BLADE** applications that reuse on-chain Request and Contract Net machinery in the evaluated BLADE Core;
2. a **purpose-built Solidity** baseline that implements the same measured interaction paths without that reusable Core.

Primary evidence is complete-interaction EVM gas (`receipt.gasUsed` summed over frozen top-level interaction transactions) plus structural LOC of Core, BLADE applications, and the purpose-built baseline.

## Main results

Under the frozen primary matrix:

- Complete-interaction gas overhead of BLADE vs purpose-built Solidity: **20.338% to 53.948%**.
- Structural: BLADE Core **539** LOC; BLADE application **82** LOC; purpose-built application **344** LOC.
- Application LOC reduction `(344−82)/344` = **76.163%**.
- Protocol LOC reduction **77.193%**.
- Application-owned protocol checks: BLADE **0**, purpose-built **101**.

LOC is a structural metric. It does not establish developer productivity, ease of use, fewer bugs, maintainability, or developer experience.

Supported trade-off (not a value judgement): BLADE trades additional EVM execution and deployment cost for reusable on-chain protocol machinery and substantially less application-owned protocol code.

Official tables and RQ write-ups: `RESULTS.md`.

```bash

```

Optional semantic A/B tests, with `blade` checked out at `c145305a3ca76f52a64b62a0cb731283dbba9638` as a sibling of this repository:

```bash
cp experiment/environment/foundry.toml foundry.toml
cp experiment/environment/remappings.txt remappings.txt
mkdir -p outputs/storage
forge test
```

`outputs/storage` is generated by `StoragePilot` and is not the published scientific storage evidence. Frozen storage measurements remain under `data/storage/`. Re-running the tests does not replace those records.

Published claims are verified from frozen raw and derived files. Full campaign re-measurement is not packaged as a self-contained public command.

## Scope and limitations

The evaluation is limited to the implemented Request and Contract Net subsets and does not establish full FIPA compliance, external interoperability, or production security.

- N=16 is secondary local-Anvil evidence under a 30M block gas limit.
- Inferential statistics are not used: each cell is one deterministic execution.
